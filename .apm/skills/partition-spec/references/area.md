# Writing the area file

Create the area file, `<specs>/<area>/area.md`, from `assets/area.md` when its first entry is validated; a person deletes it once its last entry leaves. An area rule is written like a business rule: by a person or copied from a source that states it, under its banner, never deduced. Nothing is written to it before the owner validates it: show the owner each rule and each word you would write, and write it only once validated. Show it as it would be written, every column and the file it goes to; a validation given to an entry not shown that way is no validation. A rule a person states is the source of its entry, not its validation.

Before writing a rule or a word to it, read the area files and specs of the other areas. One that the area file or a spec of another area also holds spans two areas: it goes to no area file but to the admission test of the invariant register, and you report the file and the identifier that hold it. Nothing is moved.
